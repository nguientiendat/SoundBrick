# SoundBrick Architecture

## Overview
SoundBrick is a minimal, low-resource SoundCloud player designed specifically for the TrimUI Brick Pro (Allwinner A133P).
It uses SDL2 for the UI, a C/C++ backend for SoundCloud API interaction, and relies on an external hardware-accelerated or standard media player (e.g., mpv, ffmpeg, tplayer) available on the StockOS firmware.

## Core Components

1. **UI Layer (SDL2)**
   - Minimal dependency, utilizing SDL2 for rendering and input handling.
   - Designed around a state machine (`APP_HOME`, `APP_SEARCH`, `APP_NOW_PLAYING`).
   - Runs on the main thread to ensure responsive UI.

2. **SoundCloud Client**
   - Interacts with the SoundCloud API to search tracks, fetch metadata, and resolve stream URLs.
   - Runs asynchronously using worker threads or a job queue to avoid blocking the UI.
   - Built on `libcurl` and `json-c`/`cJSON`.

3. **Audio Player Abstraction**
   - Abstract interface `AudioPlayer` that can be backed by the device's native player (e.g. `mpv`, `tplayer`).
   - Handles play, pause, resume, seek, and track lifecycle events.
   - Runs in a separate process or thread depending on the backend used.

4. **Input Manager**
   - Maps D-Pad, A, B, X, Y, L, R, Menu buttons to logical events.
   - Configurable based on SDL Game Controller / Keyboard events generated by the TrimUI Brick Pro.

5. **Cache & Data Manager**
   - Manages recent tracks (`recent.json`), app settings (`settings.json`).
   - Handles artwork downloading and local filesystem caching.

## Directory Structure
```
SoundBrick/
├── bin/          # Compiled binaries
├── lib/          # Shared libraries if necessary
├── assets/       # Fonts, icons, static resources
└── data/         # User data (recent, settings, cache)
```

## Non-Blocking Strategy
- All network requests (search, stream resolve, artwork download) are pushed to a background worker.
- Once a background worker finishes, it posts an SDL Custom Event to the main thread.
- The UI handles the event and updates the screen accordingly.
